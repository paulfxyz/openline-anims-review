# Openline delivery acceptance checklist

This checklist separates visual integration from live product behaviour. A checked UI item does not approve an unconnected backend.

## Visual integration

- [ ] Every selected key is traceable to its manifest ID, source module and destination slot.
- [ ] KYC option 0 stays current. Blog default and alternative are not mounted in the same slot.
- [ ] No rejected 16-page alternatives or full France selector layout are restored.
- [ ] Openline native font is consistent across pages, dialogs, chat and SVG labels.
- [ ] Referral orange matches its host, plus-field fade is preserved, and the original board is consistent.
- [ ] IoT starts in Chrome. Global eSIM cards/accents are orange.
- [ ] Native slot ratios, readable labels, consistent padding and transparent backgrounds pass desktop/mobile review.
- [ ] Selected motion remains intact; reduced motion, Pause, hidden-tab and offscreen behaviour are checked.
- [ ] How-it-works originals are restored from the confirmed source without reverting the two selected home replacements.
- [ ] Mobile app, Revisions top-right and condensed certification trigger are integrated into the real shared shell.

## Interaction checks

- [ ] Keyboard focus is visible; targets are at least 44px where needed; dialogs close on Escape and return focus.
- [ ] About results start expanded with every value locked; nine cities and clocks are correct.
- [ ] Contact destinations match Paul's list. Coming-soon hotline cannot dial.
- [ ] Contact support steps seek their scenes and resume, with manual control under reduced motion.
- [ ] France keeps original Data Bundles; durations have no icons; the full fair-use label opens its dialog.
- [ ] Calendar supports same-day, reversed clicks, month/year change, cancellation, reopen, reset and keyboard navigation.
- [ ] Calendar applies inclusive day count and consistent currency/quote; dates do not schedule activation.
- [ ] France FAQ support animation can be controlled and routes to KB/chat.
- [ ] Operator rows pause, browse/search works, reduced-motion rows remain scrollable, duplicate loops are hidden from accessibility.
- [ ] Installation primary action skips redemption when the user already has an eSIM.
- [ ] Start check is non-destructive; readiness is initially off; cancel does not activate.
- [ ] QR and manual fields appear in the right places; quick view/edit dialogs do not restart the flow.
- [ ] Gift unlock requires confirmation; recipient locked/pending/used states block activation.
- [ ] Recipient entry does not expose code or sender details in URL/storage; keep-for-later does not consume it.
- [ ] Chat bar and header toggle work; official mark/centred portraits remain; prompt copy errors are handled.
- [ ] Clear chat cancel preserves discussion; confirmed local UI reset returns to the welcome. Production deletion is tested separately.
- [ ] All forms have loading/error/empty/retry states; asynchronous close/unmount cancels stale UI updates.

## Content and production checks

- [ ] Apply exact copy changes and latest new-copy records, not only the illustrations.
- [ ] Fixed full-allowance guarantee, local MNO fair use and best-effort profile replacement are consistent across pages and dialogs.
- [ ] Confirm real activation-validity rules, replacement costs/balance/validity handling and support process with product.
- [ ] Reconcile coverage counts, KB/device counts, operators, certifications, competitor claims and testimonials.
- [ ] Approve Product Hunt rules/prices/date and OMDM illustrative metrics before publication.
- [ ] Replace fictitious plan/profile/QR fields with authenticated data; do not falsely assert physical connectivity.
- [ ] Implement idempotency, ownership, one-time redemption, recipient isolation and safe error/retry handling.
- [ ] Implement real persistence, email validation, server deletion/issue resolution, payments and reward issuance where required.
- [ ] Verify CSP, asset permissions, no sensitive logging, no code-bearing URLs, no credentials in the client bundle.
- [ ] Remove QA capture scaffolding/reviewer controls from customer builds, not technical documentation.
- [ ] Test at 375px, tablet and 1440px, 200% zoom, keyboard-only and reduced motion; test Safari/iOS and Chrome/Android on real target devices.
- [ ] Supply staging links and evidence; obtain Paul's final production sign-off.
